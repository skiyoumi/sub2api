# 图片创作

用户入口为侧栏「图片创作」（`/image-studio`）。选择已有 API 密钥后，页面使用该密钥请求 `/v1/models`，展示其分组可用的生图模型。切换密钥会清空旧模型和作品；提示词广场只填入描述，不改变密钥或模型。

同一浏览器标签页会按登录用户记住所选密钥 ID、模型和任务 ID。切换菜单或刷新后，页面重新鉴权查询服务器任务，优先恢复进行中的生成；后台继续执行，不依赖页面驻留。打开历史、返回可见标签页时主动刷新，列表查询失败会显示重试提示。浏览器会话存储不保存 API 密钥正文、提示词或图片。

当前接入项目现有的 OpenAI、Grok Images 异步接口，以及路由到这两个平台的合成分组。分组需要开启图片生成权限。原有 Gemini 批量生图功能不属于本页面的接口范围。生成请求仍经过现有网关的权限、额度、内容审核、账号调度和计费流程。

## 开启存储

无需先配置七牛云：未配置完整云存储时，图片自动保存在服务器 `./data/generated-images` 目录，保留两小时。管理员可在「数据备份 → 图片存储」切换到七牛云/S3 或修改本地目录。「测试连接」会写入、读回、删除一个临时测试对象；测试失败的对象也进入自动清理队列。后台保存的配置优先于 `config.yaml`，修改后立即生效。

升级时，旧版空白 S3 配置（包括默认的 `enabled: false`）自动改用本地存储；已配置的云存储继续使用。主动禁用本地存储或已配置的云存储仍会停止新任务。云配置完整但连接失败时会报错，不会静默切换位置。

### 本地存储

选择「本地存储」，填写后端服务有读写权限的目录，默认 `./data/generated-images`，相对路径以服务工作目录为基准。这里的“本地”指服务器磁盘；用户需要点击下载，才会保存到自己的电脑。

容器部署应将目录挂载到持久卷，重启后保留原路径。多实例部署必须让全部实例在同一绝对路径访问同一个共享卷，或改用七牛云/S3；独立实例磁盘不能混用。

仅使用配置文件时的示例：

```yaml
image_storage:
  enabled: true
  provider: local
  local_directory: /app/data/generated-images
  prefix: images/
  max_download_bytes: 33554432
```

### 七牛云

选择「七牛云」，使用七牛 Kodo 的 S3 兼容接口，填写私有空间的 S3 Bucket 名称、区域、S3 Endpoint、AccessKey 和 SecretKey。Endpoint 是 S3 API 地址，不是图片下载域名。区域和 Bucket 名称以七牛控制台为准。

例如华东区域的接口配置为 `https://s3.cn-east-1.qiniucs.com`、区域 `cn-east-1`。其他区域请查阅[七牛 S3 访问域名](https://developer.qiniu.com/kodo/4088/s3-access-domainname)和[S3 兼容说明](https://developer.qiniu.com/kodo/4087/compatible-s3-api)。凭证需要该图片前缀的写入、读取（含 HEAD）、删除权限；开启版本控制时，还需要删除对象版本的权限。

服务需配置固定的 `TOTP_ENCRYPTION_KEY`，用于加密保存在数据库中的存储凭证。不要在仍有待清理图片时删除旧凭证、取消删除权限或更换这把加密密钥，否则清理将失败并持续重试。云存储缺少固定加密密钥时不会启用。

也可选择通用 S3 兼容存储，沿用现有备份 S3 配置；图片采用独立的 `images/studio/<uuid>` 对象路径。

## 两小时保留与清理

- 图片落盘或上传成功后保留两小时；接口会检查图片和任务的有效期及用户、API 密钥归属，到期立即拒绝访问。浏览器同时清除过期作品的预览。
- 服务启动时及每分钟扫描 PostgreSQL `image_assets` 清理日志，删除文件或云对象后才删除日志。通常在到期后一分钟内释放空间；网络故障、权限问题或大批量积压时可能延后，恢复后继续重试。
- 写入图片前先保存清理日志。每张图片记录当时的存储配置和加密凭证，服务重启、关闭生图功能、切换存储位置后仍会清理旧图片。失败任务中已写入的部分图片也会被清理。
- Redis 保留任务状态、受保护的图片路径以及原始提示词、模型、尺寸、质量和数量，不保存图片 base64 或参考图数据。历史作品按所选密钥显示最近 50 个有效任务，任务完成后保留两小时。提示词与任务共用 TTL，到期一同清除；历史和结果页支持复制、填入提示词，不自动提交或改变当前密钥。升级前未记录的原始提示词无法追溯补齐。
- 前端通过带鉴权的 `/v1/images/assets/:id` 读取图片，不暴露云存储直链或凭证。响应使用 `Cache-Control: private, no-store`。请使用私有桶，反向代理不得缓存该接口。旧配置中的 `public_base_url` 和 `presign_expiry_hours` 不再用于这些异步任务。
- 已下载到用户电脑的文件不受服务端删除影响。升级前生成的旧对象没有清理日志，本功能不会扫描或删除那些对象。

数据库迁移 `238_image_assets.sql` 随服务正常启动应用。无需配置系统 cron。服务停机期间无法执行物理删除，重启后会补扫。

## 页面能力

支持文生图、单张参考图再创作、1–4 张输出、比例/分辨率/质量设置、提示词分类、结果预览、下载、作为参考图继续创作及历史任务查看。参考图支持 PNG、JPG、WebP，最大 10 MB。参数选项按模型系列支持情况收敛，实际可用能力与额度仍由网关及上游验证。

宽高比支持 1:1、5:4、9:16、21:9、16:9、3:2、4:3、4:5、3:4、2:3，并配有用途说明。预设尺寸保持准确比例且对齐 16 像素，页面显示实际请求尺寸；分辨率档位为近似等级。自定义尺寸接受正整数宽高，前端原样发送 `size: "宽x高"`，不缩放或取整。Grok 沿用现有网关转换逻辑，将尺寸转为支持的比例与分辨率，不能保证输出像素与自定义值一致；页面会显示此提示。

## 核对请求与结果

参数面板表示下一次生成的请求目标，改变表单不会改变旧作品的请求记录。结果区保留图片预览、下载和生成提示词，不显示尺寸/质量对比卡片及参数不一致提示。实际像素仍由存储服务读取 PNG、JPEG、WebP 文件头确定，覆盖上游可能不准确的尺寸字段；历史记录保留已记录的请求和输出尺寸，供需要时核对。

原图下载不自动放大、裁剪或再次调用模型。多个结果可以有不同尺寸，所有尺寸记录随任务的两小时 TTL 清除。质量字段是上游报告的参数，不是对画质的测量。

新生成的作品会额外保存最长边不超过 1024 像素、JPEG 质量 80 的预览图（透明区域以白色显示），仅在预览文件比原图更小时使用。页面优先读取预览图，点击「下载原图」或「用作参考图」才获取完整原图；原图字节、尺寸和格式保持不变。预览图使用相同的鉴权接口、任务归属校验及两小时清理流程。旧作品、无法解码或超过 32 MP 的图片，以及预览生成/存储失败的作品继续使用原图。此优化需要同时更新前后端，无需数据库迁移，不会给旧作品补生成预览图。

OpenAI API Key 路由会透传 `size`、`quality`，OAuth 路由把它们传入 Responses 的 `image_generation` 工具；项目已有回归测试覆盖 OAuth 上游返回 `auto` 与不同实际尺寸的情形。模型别名或分组路由也可能对应不同上游能力，因此不能仅凭参数面板判断输出已达到该尺寸。`gpt-image-2` 的 `3840x2160` 是[官方文档列出的合法尺寸](https://developers.openai.com/api/docs/guides/image-generation#earlier-gpt-image-models)，应以具体任务的请求记录和文件像素排查偏差。

OAuth 还会把合法的显式尺寸、画布方向和质量写入 Responses 驱动模型的执行指令，要求实际工具调用沿用它们，避免仅依赖可能被上游归一化为 `auto` 的工具配置。此约束与用户原始提示词分开；未指定参数或明确选择 `auto` 时不追加约束。上游无法遵守时要求报告不支持，保留实际尺寸校验，不把提示指令当作输出尺寸保证。需要严格尺寸控制时，应在实际使用的上游验证参数支持；无法遵守的 OAuth 通道需要换用支持该尺寸的原生 Images API 通道。

2026-09-15 的 Docker 排查验证了上述限制：已包含显式执行指令的容器仍通过 OAuth 返回 `1024x1536`，而任务请求为 `gpt-image-2`、`3840x2160`、`high`，结果质量为 `auto`；服务器 PNG 文件头与任务结果一致。经用户授权，对同一账号进行了 `tool_choice: "none"` 的非生图参数探测：发送到 `https://chatgpt.com/backend-api/codex/responses` 的工具参数为 `gpt-image-2`、`3840x2160`、`high`，但 HTTP 200 响应的 `response.created` 和 `response.completed` 均将工具配置报告为 `gpt-image-2-codex`、`auto`、`auto`，没有生成图片。这证明该账号的上游在请求创建阶段就归一化了工具参数，增加执行指令并不能解决其严格尺寸控制问题。Codex 官方仓库也有[同类用户报告](https://github.com/openai/codex/issues/28723)，但这不是对所有账号能力的保证或官方承诺。

遇到这种情况，先查看 Docker 日志中的 `Images request routing` 和账号类型，再核对密钥所属分组绑定的实际账号。分组名称含有“原生 4K”不代表其绑定的 OAuth 通道具备此能力。需要精确 4K 时，为分组绑定经验证支持该尺寸的 OpenAI 兼容原生 Images API 账号，并通过实际生成验证模型映射、尺寸和质量；不能把同一个 OAuth 令牌改成 API Key 类型使用，也不能靠放大图片冒充原生 4K。

`frontend/src/assets/image-studio/inspiration.png` 是提示词广场的静态示例素材，不属于用户生成文件，不参与两小时清理。它由 Vite 打包为 `/assets/inspiration-<hash>.png`；不要放回 `/images/`，该前缀是后端的生图 API 路由。
